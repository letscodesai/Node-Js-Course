Practice 2: Sakila database & REST APIs

Movies & Actors.

Build CRUD and query APIs with Node.js, Express.js and MySQL on the Sakila movie database. Nine endpoints, two of them real challenges.

Node.jsExpress.jsMySQLmysql2SQL JOIN

1Problem Description

Given an app.js file and the Sakila MySQL database, write APIs to perform CRUD operations and retrieve information from the database.

You will be working primarily with the following three tables:

filmTable 1
film_idPKINTEGER
titleVARCHAR
descriptionTEXT
release_yearYEAR
language_idINTEGER
rental_durationINTEGER
rental_rateDECIMAL
lengthINTEGER
actorTable 2
actor_idPKINTEGER
first_nameVARCHAR
last_nameVARCHAR
film_actorTable 3
actor_idFKINTEGER
film_idFKINTEGER
last_updateTIMESTAMP

Note: The film_actor table establishes the relationship between films and actors. A film can have multiple actors, and an actor can appear in multiple films.

Important: Use the existing Sakila database. Do not create new tables.

Note: The table columns use snake_case (for example release_year), but the API requests and responses use camelCase (for example releaseYear).

2Instructions

  • Use MySQL as the database, with the existing sakila database.
  • Use the mysql2 package to connect MySQL with Node.js.
  • Use Express.js to create the APIs.
  • Use npm install to install the required packages.
  • Export the Express instance using the default export syntax.
  • Use SQL queries to perform all database operations.

3API Specifications

API 1GET/films/

Description: Returns a list of all film titles in the film table.

Response

JSON
[
  {
    "filmId": 1,
    "title": "ACADEMY DINOSAUR"
  },
  {
    "filmId": 2,
    "title": "ACE GOLDFINGER"
  }
]
API 2POST/films/

Description: Creates a new film in the film table and associates an actor with that film in the film_actor table. The film_id is auto-incremented.

Request

JSON
{
  "title": "Jurassic Park",
  "description": "A dinosaur adventure movie",
  "releaseYear": 1993,
  "languageId": 1,
  "rentalDuration": 5,
  "rentalRate": 2.99,
  "length": 127,
  "actorId": 10
}

Response

Text
Film Successfully Added
API 3GET/films/:filmId/

Description: Returns the details of a film based on the film ID.

Response

JSON
{
  "filmId": 1,
  "title": "ACADEMY DINOSAUR",
  "description": "A Epic Drama of a Feminist And a Mad Scientist",
  "releaseYear": 2006,
  "rentalDuration": 6,
  "rentalRate": 0.99,
  "length": 86
}

Note: rentalRate must be a number (0.99), not a string. MySQL DECIMAL values may come back as strings from mysql2, so check the type in your response.

API 4PUT/films/:filmId/

Description: Updates the details of a film in the film table based on the film ID.

Request

JSON
{
  "title": "The Amazing Spider-Man",
  "description": "A superhero adventure movie",
  "releaseYear": 2012,
  "rentalDuration": 5,
  "rentalRate": 3.99,
  "length": 136
}

Response

Text
Film Details Updated
API 5DELETE/films/:filmId/

Description: Deletes a film from the film table based on the film ID. If the film has associated records in the film_actor table, those records should also be deleted.

Response

Text
Film Removed
API 6GET/actors/

Description: Returns a list of all actors in the actor table.

Response

JSON
[
  {
    "actorId": 1,
    "firstName": "PENELOPE",
    "lastName": "GUINESS"
  },
  {
    "actorId": 2,
    "firstName": "NICK",
    "lastName": "WAHLBERG"
  }
]
API 7GET/actors/:actorId/films/

Description: Returns a list of all film titles associated with a specific actor.

Response

JSON
[
  {
    "title": "ACADEMY DINOSAUR"
  },
  {

Additional Challenge APIs

These two APIs are intentionally designed to be slightly more challenging. Think about the database relationships and SQL concepts before writing the queries.

API 8GET/films/:filmId/actors/Medium

Description: Returns the details of all actors who have acted in a particular film based on the film ID. You need to retrieve information from both the actor and film_actor tables.

Response

JSON
[
  {
    "actorId": 1,
    "firstName": "PENELOPE",
    "lastName": "GUINESS"
  },
  {
    "actorId": 10,
    "firstName": "CHRISTIAN",
    "lastName": "GABLE"
  }
]

Hint: Think about how you can retrieve actor details using the relationship between the actor and film_actor tables. You will need an SQL JOIN.

API 9GET/actors/film-count/Medium

Description: Returns a list of actors along with the total number of films they have acted in. The response should include all actors, even if an actor has no associated films.

Response

JSON
[
  {
    "actorId": 1,
    "actorName": "PENELOPE GUINESS",
    "totalFilms": 19
  },
  {
    "actorId": 2,
    "actorName": "NICK WAHLBERG",
    "totalFilms": 25
  }
]

4How to Test Your APIs

Create an HTTP file (for example test.http) in your project and write one request for each endpoint listed below. Send the requests in the order given and check the points mentioned for each one. The DELETE request is last because it removes the film added by the POST request. Change the port in the URL if your server runs on a different one.

RequestURLWhat to check
GET http://localhost:3000/films/
  • Status is 200 OK.
  • The response is an array of all films (1000 in a standard Sakila database).
  • Each item has only filmId and title.
POST http://localhost:3000/films/
  • Send the JSON request body given in API 2 with the header Content-Type: application/json.
  • The response text is exactly Film Successfully Added.
  • Send the GET all films request again. The new film appears at the end with an auto-generated ID. Note this ID, you need it for the last test.
  • In MySQL Workbench run SELECT * FROM film_actor WHERE film_id = <new film ID>;. A row for actor 10 exists.
GET http://localhost:3000/films/1/
  • The response is a single object (not an array).
  • It shows ACADEMY DINOSAUR with exactly the keys filmId, title, description, releaseYear, rentalDuration, rentalRate, length.
  • rentalRate is a number, not a string.
PUT http://localhost:3000/films/1/
  • Send the JSON request body given in API 4 with the header Content-Type: application/json.
  • The response text is exactly Film Details Updated.
  • Send the GET request for film 1 again. The details now match the request body.
  • Other films and the film's language_id are unchanged.
GET http://localhost:3000/actors/
  • The response is an array of all actors (200 in a standard Sakila database).
  • Keys are in camelCase: actorId, firstName, lastName.
GET http://localhost:3000/actors/1/films/
  • The response is an array of objects with only a title key.
  • The list includes ACADEMY DINOSAUR.
  • After the POST test, send the same request for actor 10. The new film's title is in the list.
GET http://localhost:3000/films/1/actors/
  • The response is an array of actors with actorId, firstName, lastName.
  • Actors 1 and 10 are in the list.
  • Send the request with the new film's ID. Only actor 10 is returned.
GET http://localhost:3000/actors/film-count/
  • Each item has actorId, actorName (first and last name joined by a space) and totalFilms (a number).
  • The first two actors are PENELOPE GUINESS (19) and NICK WAHLBERG (25) in a standard Sakila database.
  • Insert an actor with no films in MySQL Workbench. That actor still appears, with totalFilms as 0.
DELETE http://localhost:3000/films/<newFilmId>/
  • Use the ID of the film you added in the POST test. Original Sakila films are referenced by other tables (such as inventory), so deleting them can fail.
  • The response text is exactly Film Removed.
  • Send the GET all films request again. The film is no longer in the list.
  • In MySQL Workbench, film_actor has no rows for that film_id.

Tip: Running the POST request again adds one more film each time. If you want to start from the original data, remove the extra films using your DELETE API.
